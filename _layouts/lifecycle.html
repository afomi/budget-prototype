Verification boundary and optional BPMN formalization
The lifecycle is the reusable process definition; FY 2028 is one instance. The $10 execution scenario is a worked example within that instance. Git branches version the supporting documents, and a PR merge approves a document version. An optional Touchpoints BPMN export can formalize the same lifecycle later, alongside the SVG.
Traceability follows explicit parent and revision references. Authorization verifies ECDSA signatures against a local allowlist and checks a separate approval signature bound to the exact document digest. The approval signature simulates an approved/merged document; the browser does not merge a GitHub PR.
The signed records and hash-linked receipts are real computations. Source identities, approvals, financial systems, and the permissioned ledger are local simulations. Keys are generated for this session. Real identity requires a trusted external key registry and approval process. There is no distributed consensus, chain anchoring, money movement, or UTXO transaction here.
Reapportionment appends a new ceiling and references the earlier decision. It cannot fall below existing allotments or exceed the appropriation. Monitoring cases demonstrate invalid source evidence; they are retained as exceptions without changing the accepted authority history.
The model covers this basic scenario only. Production funds-control law, account lifecycle, payment reconciliation, and network integration remain outside this demonstration. The evidence export omits source financial records; verification needs those separately and a trusted registry.
